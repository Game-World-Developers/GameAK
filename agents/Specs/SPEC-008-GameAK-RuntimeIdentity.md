# SPEC-008: Runtime Identity

Status: IMPLEMENTED

Last validated by Ralph: 2026-06-13

---

## Summary

This specification defines Runtime Identities, the stable identifiers used to reference Data Blocks within the GameAK Runtime.

Runtime Identities are the mechanism by which Controllers, Commands, and Queries address simulation state without depending on memory layout or representation.

---

## Core Requirements

### 64-bit Value

A Runtime Identity is a 64-bit unsigned integer value.

The underlying type must not be exposed to runtime consumers as a raw integer.

### Runtime Generated

Runtime Identities are generated exclusively by the Runtime.

Consumers must not create or assign Runtime Identities.

### Unique Per Instance

Runtime Identities must be globally unique within a Runtime instance.

Destroyed identities must not be reused.

### Stable

A Runtime Identity remains stable for the entire lifetime of its associated Data Block.

Identity stability is independent from memory location, layout, and representation.

### Comparable

Runtime Identities must support equality and inequality comparison.

Runtime Identities must be hashable.

### Invalid Identity

The Runtime must define a sentinel value representing an invalid identity.

Operations on invalid identities must produce explicit errors.

---

## Constraints

* Runtime Identities are 64-bit values.
* Runtime Identities are generated by the Runtime.
* Runtime Identities are not memory addresses.
* Runtime Identities are not array indices.
* Runtime Identities are not reused after destruction.
* Runtime Identities must be stable across layout changes.
* Runtime Identities must be stable across representation changes.

---

## Out of Scope

* Serialization format.
* Network identity mapping.
* Persistent identity across Runtime instances.

---

## Open Questions

* [ ] Should Runtime Identity be a class type or a typed wrapper?

**Answer:** Runtime Identity is a class type wrapping a 64-bit unsigned integer.

The wrapper provides type safety, prevents implicit conversions, and ensures that identities cannot be confused with plain integers.

* [ ] How are Runtime Identities generated?

**Answer:** Runtime Identities are generated using a monotonically increasing counter.

The counter starts at 1. Zero (0) is reserved as the invalid identity sentinel.

The counter is managed exclusively by the Runtime and is not exposed to consumers.

* [ ] Should the generation strategy be configurable?

**Answer:** No.

The generation strategy is an internal Runtime concern.

Alternative strategies may be introduced in future versions but must remain transparent to consumers.

* [ ] Can Runtime Identities be compared for ordering (less/greater)?

**Answer:** Yes.

Runtime Identities support full relational comparison for use in sorted containers.

Comparison order matches identity generation order.

---

## Definitions

### Runtime Identity

A stable 64-bit identifier assigned to a Data Block by the Runtime.

### Invalid Identity

A sentinel identity value (zero) that does not reference any Data Block.

### Identity Generation

The process of producing a new unique Runtime Identity.
